## Change request
Avoid streaming if stopped at the request handshake

Depending on the server behaviour, the very initial handshake of the stream can be slow too: before the headers are sent. Some clients, such as aiohttp, do not consider the request as ready to be consumed until at least the headers are received. As a result, Kopf's internal API machinery does not finish the `session.request()` call yet.

As such, depending on circumstances, the stopper can be triggered either when actually streaming the content, or when waiting for the initial headers. The former case was already covered. The latter case was not. Now, it is covered: the stopper will also terminate the pending request handshake if the headers are not yet received from the server.

Detected while refactoring the tests to KMock, where there was a clear distinction between timeouts before and after the first useful payload is sent.
